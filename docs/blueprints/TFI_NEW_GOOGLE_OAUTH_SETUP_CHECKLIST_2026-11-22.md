## Owner setup required in Google Cloud

1. Open Google Cloud Console and select/create the project that will own the TFI OAuth client.
2. In APIs & Services > Library, enable Google Sheets API.
3. Configure Google Auth Platform / OAuth consent screen:
   - Set the app name and support email.
   - Configure audience according to the intended users.
   - If the app is External and remains in Testing, add the Google account that will connect to TFI as a test user.
   - Complete required developer contact information.
4. In APIs & Services > Credentials, create an OAuth Client ID:
   - Application type: Web application.
   - Authorized redirect URI (exact):
     http://127.0.0.1:5100/api/google-sheets/callback
5. Copy the generated Client ID and Client Secret directly into the local file:
   C:\Users\Rominick\Desktop\TFI_NEW\.env

   Add or update these two lines:
   TFI_GOOGLE_CLIENT_ID=YOUR_CLIENT_ID
   TFI_GOOGLE_CLIENT_SECRET=YOUR_CLIENT_SECRET

6. Save .env locally. Do not send the Client Secret, refresh token, or administrator password in chat. Do not add credentials to .env.example, documentation, frontend code, or source control.
7. Restart the TFI_NEW backend so the new environment variables are loaded.
8. Sign in to TFI_NEW using an account with Import Center view permission.
9. Open Import Center and choose Connect Google Account. Authorize the Google account that has access to the official workbook.
10. Confirm the UI shows a connected account. Then inspect the official workbook URL and select one module only.

## OAuth callback SameSite compatibility fix — 22 November 2026

Before asking the owner to start live Google authorization, the callback path was reviewed against the TFI login cookie policy. The TFI session cookie remains SameSite=Strict; therefore it must not be weakened merely to accommodate Google's cross-site redirect.

Implemented in TFI_NEW:
- GoogleSheetsService.complete_authorization_for_state(state, code) resolves the initiating TFI user from the existing one-time server-side OAuth pending-state record.
- The callback consumes the state once and validates its user binding, expiry, and stored PKCE verifier through the existing token exchange flow.
- GET /api/google-sheets/callback no longer requires the TFI session cookie; it relies on the unguessable, expiring, one-time server-side OAuth state and PKCE verifier.
- Normal TFI login cookie remains HttpOnly and SameSite=Strict.
- Unknown, expired, or replayed OAuth states are rejected.
- No Google credentials or tokens are exposed to the browser.

Regression coverage:
- Real GoogleSheetsService callback state flow tested with a fake token/userinfo provider.
- Callback route tested without a TFI session cookie.
- Existing import-service OAuth callback test updated to simulate authorization start before callback.

Full backend suite after patch: 167 passed.
