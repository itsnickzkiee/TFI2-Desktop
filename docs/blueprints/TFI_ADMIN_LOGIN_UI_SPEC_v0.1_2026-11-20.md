# TFI_NEW — Admin Login UI Specification v0.1

**Date:** 20 November 2026  
**Project:** TFI_NEW  
**Module:** Admin Login and Session  
**Status:** UI preview implemented; local interaction-tested; authentication/session service not connected

## 1. Basis and purpose

The TFI New Admin Module Blueprint lists **Admin Login and Session** as the first Admin function. No dedicated login preview existed in the current design folder. This specification establishes the initial pre-authentication screen for the Admin portal.

The screen is a standalone entry page, not a sidebar module. It is intended to be the first screen shown before the authenticated application shell is mounted.

## 2. UI composition

- Tosen Foods logo using the existing project asset.
- TFI Production Management System branding.
- Administrator access heading and short sign-in description.
- Username or email field.
- Password field.
- Show/Hide password control.
- Sign in button.
- Accessible inline required-field feedback.
- Explicit preview-only notice.
- Responsive desktop and mobile layout.
- No authenticated dashboard content or operational data is shown before sign-in.

## 3. Field and interaction behavior

| Element | Behavior |
|---|---|
| Username or email | Text input; required; autocomplete username |
| Password | Password input; required; autocomplete current-password |
| Show/Hide | Toggles password visibility; exposes pressed state and accessible label |
| Sign in | Checks only whether both fields contain text, then shows the preview-only notice |
| Required-field feedback | Focuses the missing field and announces a concise error |
| Preview-only response | Clears entered values and states that credentials were not checked and no session was created |

The local preview does not call an authentication provider, server, database, or external endpoint. It does not persist entered credentials in browser storage or create a session.

## 4. Security and policy boundaries

The following decisions remain open and must not be inferred from the visual preview:

- Authentication provider and sign-in identifier policy.
- Password policy and recovery/reset process.
- Multi-factor authentication requirements.
- Session lifetime, idle timeout, refresh, and revocation behavior.
- Failed-login throttling, lockout, and recovery rules.
- Whether multiple administrator accounts are permitted.
- Final administrator roles and permission enforcement.

The preview intentionally omits Remember Me, Forgot Password, account registration, and any fabricated credentials. Do not enter real credentials into the preview.

## 5. Design alignment

- Uses the existing Tosen Foods logo and TFI green/red brand palette.
- Uses the existing Segoe UI/Inter/Arial typography family.
- Uses a standalone pre-authentication layout rather than the authenticated sidebar shell.
- Provides visible keyboard focus, semantic labels, inline status feedback, and reduced-motion support.
- At mobile widths, the brand panel stacks above the sign-in form without page-level horizontal overflow.

## 6. Acceptance criteria

- Logo asset loads successfully.
- Desktop and mobile layouts render without page-level horizontal overflow.
- Username and password fields are keyboard accessible.
- Empty username and empty password produce field-specific feedback.
- Show/Hide password changes the input type and accessible state.
- Submitting both fields displays the explicit preview-only response.
- Submitted values are cleared after the preview response.
- No credential is transmitted or persisted.
- No authenticated session is created.
- No external request, browser error, or console error is generated by the page.

## 8. Completion boundary

This deliverable is a visual and interaction prototype only. It does not provide real authentication, session management, account recovery, role checks, or backend security. The Admin Login and Session service must be implemented only after the authentication and session policies are approved.

No Google Sheets cells, operational records, Supabase schema, database records, user accounts, or permissions were created or changed.
