Data & import policies

Operational rules confirmed in the TFI Admin Module blueprint.

Blueprint confirmed
New mapped records with incomplete fieldsConfirmed

Insert into the correct module table and mark the record Incomplete. Missing information must not be invented.

Exact duplicatesConfirmed

Do not create a second module record when an existing duplicate is verified. Preserve the link to the existing record where identified.

Possible duplicatesConfirmed

Hold for Admin review. Do not automatically insert or delete a record while the match is uncertain.

Unmapped or unparseable rowsConfirmed

Keep the source row in the Central Import Inbox until its destination or parsing issue is resolved.

Derived, report, and helper rowsConfirmed

Do not treat formula-only, report, or helper rows as independent operational transactions. Record the exclusion reason for traceability.

Source method still needs a decision. The Admin blueprint leaves open whether the Admin will upload an XLSX file or provide an authorized Google Sheets link for a one-time controlled scan. Continuous Google Sheets synchronization is not part of normal operations.

Session lifecycle

Expected behavior once the approved policy is implemented.

Design reference
01
Sign inAdministrator completes authentication and receives a secure session.
02
Monitor activityThe server evaluates the configured inactivity and maximum-lifetime limits.
03
Show warningTFI displays the selected warning window and countdown before expiry.
04
Extend or expireAn approved extension is validated, or the session is revoked and the user returns to sign in.
05
Record the eventSecurity-relevant session activity is recorded in the Audit Trail without storing credentials or tokens.
!
Implementation requirement

Final session expiry must be enforced by the trusted backend, not by a browser countdown alone. The server must validate session age, revoke expired sessions, and protect session credentials using the approved authentication design.
